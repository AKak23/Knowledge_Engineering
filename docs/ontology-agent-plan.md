# 本体智能体设计草案

最后更新：2026-08-28

状态：阶段 3 规划。当前前端只能创建本地配置，没有智能体运行或发布服务。

## 产品形态

一个本体可以拥有多个智能体，每个智能体绑定一个明确的本体发布版本。首期提供两种模式：

- `knowledge`：本体知识问答。复用现有 Graph RAG、本体证据和节点/关系高亮，强调可追溯回答。
- `professional`：专业回答推理。在知识问答基础上增加领域指令、规则判断、业务行动解释和建议。

二者共享检索和证据层，但提示词、允许的工具、输出格式和发布权限可以不同。

## 建议配置

```json
{
  "id": "agent_xxx",
  "ontologyId": "ont_xxx",
  "ontologyVersion": "v3",
  "mode": "professional",
  "name": "quality-expert",
  "displayName": "质量专业智能体",
  "description": "",
  "instructions": "",
  "status": "draft",
  "invokeName": "quality-expert-v1",
  "capabilities": ["qa", "reasoning", "rule_explain"],
  "createdAt": "2026-08-28T00:00:00+08:00"
}
```

前端现有字段可以映射到以上结构，但 `published` 当前只是占位，不代表已真正发布。

## 运行链路

```text
调用请求
  -> 鉴权与智能体版本解析
  -> 加载绑定的本体发布版本
  -> Graph RAG 召回对象、实例、关系与来源证据
  -> 可选加载规则命中和行动定义
  -> 按智能体模式组装提示词
  -> 返回答案、证据、节点/边高亮和规则解释
```

专业智能体可以提出业务行动建议，但默认不能直接执行有副作用的 API。若后续开放行动执行，需要单独的工具白名单、参数校验、用户确认、幂等键、超时/重试和完整审计。

## 生命周期与版本

- `draft`：可编辑，不对外调用。
- `published`：生成不可变发布版本和稳定调用标识。
- `disabled`：停止新调用，保留历史审计。
- 本体发布新版本时，已有智能体继续绑定旧版本；升级必须显式操作并重新验证。
- 删除本体前检查智能体引用，不能留下悬空发布配置。

## 建议 API（待平台接口确认）

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/ontologies/{ontologyId}/agents` | 创建智能体草稿 |
| `GET` | `/ontologies/{ontologyId}/agents` | 列出本体下智能体 |
| `PUT` | `/agents/{agentId}` | 更新草稿配置 |
| `POST` | `/agents/{agentId}/publish` | 发布并绑定本体版本 |
| `POST` | `/agents/{agentId}/invoke` | 平台内调用 |
| `POST` | `/agents/{agentId}/disable` | 停用发布版本 |

## 验收重点

- 同一本体下多个智能体的配置、会话和权限互不污染。
- 回答只使用绑定版本的本体证据；证据不足时明确说明。
- 返回内容能驱动现有 2D/3D 图谱高亮。
- 发布调用具有鉴权、限流、日志、错误码和可追踪版本。
- 本体版本升级、规则变化和模型变更均可审计且可回滚。
