# 产品融合文档索引

这里记录根 README 未覆盖的产品决策、前端工作台现状和下一阶段设计。跨会话接手时建议按以下顺序阅读：

1. `../AGENTS.md`：仓库命令和协作约束。
2. `../PROGRESS.md`：当前真正完成到哪里、有什么限制。
3. `../PLANS.md`：阶段目标、依赖和验收门槛。
4. `product-decisions.md`：历史讨论形成的稳定产品决策。
5. `frontend-ontology-workbench.md`：现有前端交互、状态和文件边界。
6. `domain-contract-draft.md`：等待接口文档确认的领域数据契约草案。
7. `backend-integration-plan.md`：阶段 2 的后端接入方案。
8. `ontology-agent-plan.md`：阶段 3 的本体智能体设计、Pi Agent 运行层与已实现 API。

`ontology_construct/docs/` 继续保存构建流水线、结构化数据和 Graph RAG 的专项技术文档；根级 `docs/` 只负责本次产品融合，不重复拷贝那些内容。

## 文档状态约定

- **事实**：代码中已经存在，并注明验证方式。
- **已决定**：产品讨论已确认，但可能尚未实现。
- **草案**：为推进讨论提出，接口文档到位前不可视为冻结契约。
- **待确认**：不同选择会影响数据或架构，需要用户/团队明确。

维护规则：实现状态写进 `PROGRESS.md`，未来工作写进 `PLANS.md`，长期有效的设计细节写进本目录；同一事实只保留一个主要来源，其余文档使用链接指向。
