# 产品范围与已确认决策

最后更新：2026-09-04

## 产品边界

产品原型 `knova-product-prototype-20260826-160829` 用于理解少量页面的功能逻辑，不作为代码、组件或视觉实现来源。最终界面继续使用 LOM 的深色图谱美学、布局语言和交互习惯，只把相关功能逐项融合进 `lom-main`。

本轮只关注原型中的“逻辑层 → 本体构建 → 数据源兼容模式”。原型的其他页面以及超过 1.9 万行的 `workbench.js` 不在迁移范围内。

## 术语对齐

| 产品叫法 | LOM 中的含义 | 决策 |
|---|---|---|
| 本体画布 | 原本的本体层 / schema 层 | 同一个概念，升级为可编辑形态 |
| 本体画布 3D | 当前本体工作副本的三维投影 | 只读展示，复用实例 3D 的视觉与操控模式 |
| 本体实例 2D | 实例层二维视图 | 只读浏览 |
| 本体实例 3D | 原有实例三维图谱 | 只读浏览 |
| 对象 | 本体对象类型 / 类 | 画布可编辑，实例归属于对象 |
| 规则 | 对实例属性进行结构化判定的业务规则 | 独立于普通三元组和 QA 语义规则 |
| 行动 | 规则命中后可执行或建议的业务行动 | 与规则、目标对象显式关联 |
| 本体知识问答 | 当前基于本体的推理问答 | 作为智能体模板之一复用 |
| 本体智能体 | 绑定特定本体的专业回答与推理能力 | 一个本体可创建多个并可发布调用 |

## 页面与交互决策

- 左下角使用“本体画布 / 本体实例”和“2D / 3D”两组开关组合四种视图，不新造独立页面体系。
- 本体画布顶部包含：新建本体、本体数据源、添加元素、保存本体；对象、规则、行动和“流程 / 关系”收进“添加元素”弹出菜单，全局“本体智能体”入口位于底部控制栏。
- 本体实例 2D/3D 中对象、规则和行动的创建入口禁用，避免误以为实例层可以改 schema。
- 单击节点沿用 LOM 行为，在侧边固定显示摘要；双击节点打开详细配置弹窗；已有关系单击直接打开关系配置。
- 对象使用圆点，规则使用三角形，行动使用菱形；名称/描述不长期塞进节点内部。
- 关系采用直线箭头，按起终点类型使用不同颜色和虚实线。普通拖拽只用于自由移动节点；创建关系必须先点击“添加元素 > 流程 / 关系”，再依次点击起点和终点。“流程”在当前领域模型中是节点连接，不单独增加一种节点类型。
- 未加载本体时四种视图都可进入并显示空态；刷新不自动把本地草稿当作已加载本体。
- 本体画布和实例 2D 在 100% 下也可向任意方向平移；加载、重置与缩放保持图谱整体居中，实例 2D 使用与 3D 一致的背景。
- 本体画布节点允许拖入负逻辑坐标，二维 stage 必须随节点向四周动态扩展；实例 2D 节点可拖动布局，但不改变后端实例数据，所有关系线与线中点说明实时跟随。
- 节点描述默认开启；节点说明永久绑定节点，关系说明永久绑定连线中点。本体画布首次生成/加载时还需减少关系交叉和连线穿越无关节点；缩放、平移或描述开关不重新布局，所有文字与图形同步缩放。
- “新建本体”是统一的本体创建/导入/历史加载入口；右侧“构建设置”只保留本体构建模型和问答推理模型选择。新建本体弹窗不覆盖全屏暗化/模糊蒙版，构建成功加载新图后自动关闭，模型对比隐藏配置不得在弹窗底部显示。
- 右侧对话栏允许折叠成窄侧栏并随时展开；折叠时左侧画布获得剩余宽度并重新适配。保存本体后应明确显示当前本体名称，但在后端工作区 API 完成前仍需标明它是浏览器草稿。
- 当前本体名称与版本固定在“新建本体”工具栏下方，跨画布和实例视图生效；点击后展示 completed job 父子链形成的修改历史并允许切换版本。当前版本相对父版本新增的节点统一以同一种绿色描边高亮。本地人工修改只标识为本地修改，在服务端工作区版本完成前不伪造成历史版本。
- 原“节点类型”和本体画布元素/连接图例合并为右上角统一“本体图例”，整体可折叠且折叠后保留标题栏。
- 仅在本体实例 2D/3D 左侧、当前本体标识下方显示可折叠的本体规则列表。本体画布不显示规则列表；折叠只隐藏具体规则，标题栏和规则数始终保留。点击规则后留在当前实例视图，高亮命中实例和一跳关系。

## 数据源与数据挂载决策

- LOM 已能处理结构化和非结构化输入，不按原型拆成两个独立模块；必要时只在同一入口中切换配置。
- 对象需要显式“挂在数据上”，即保存对象/属性到真实数据来源的映射。
- 映射来源必须区分：`auto` 自动识别、`manual` 人工新增、`corrected` 人工修正。
- 结构化数据至少需要数据源、表/视图位置和主体字段映射；非结构化数据至少需要文件/文档、片段位置和证据标识。
- 规则条件保存结构化字段、运算符和值，不把自由 SQL 当作规则定义。

## 规则与行动决策

- 当前后端主要从材料中抽取实体、属性、三元组、行动和实例；业务规则仍需独立建模和构建。
- 规则至少包含作用对象、AND/OR、条件列表、状态和来源；规则命中结果应可解释并关联到实例证据。
- 行动至少包含类型、触发规则、目标对象、执行器/调用标识、行动计划和反馈回流说明。
- 前端可先展示和编辑；生产判定必须由后端规则引擎复现，不能依赖浏览器计算结果。

## 智能体决策

- 每个完成的本体可创建一个或多个智能体。
- 专业推理智能体面向某一领域做回答、解释和推理；本体知识问答复用当前图谱推理问答链路。
- 第三阶段已实现基于 completed ontology job 的版本绑定、发布版本和 `X-Agent-Key` 外部调用；租户权限、审批、配额与限流仍待平台化。

## 待确认

- 团队接口文档中的对象、规则、行动、数据挂载字段和 ID 规范。
- 规则是否需要嵌套条件组、时间窗口、集合运算、优先级、冲突消解和版本生效区间。
- 行动是只给出建议，还是允许自动调用 API/任务；失败、重试和幂等如何定义。
- 本体与智能体的所有者、可见范围、发布审批和外部调用鉴权方式。
