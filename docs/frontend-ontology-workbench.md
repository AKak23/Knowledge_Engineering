# 本体编辑工作台前端说明

最后更新：2026-09-02

状态：第一阶段已实现，等待产品验收。本文描述当前代码事实，不代表后端契约已经冻结。

## 文件职责

- `index_V0427.html`：工作台工具栏、层级/维度视图开关与容器、本体画布双图例、缩放控件、规则列表和配置弹窗的 DOM。
- `frontend/app.css`：LOM 基础样式以及工作台节点、规则面板、弹窗和高亮样式。
- `frontend/app.js`：原有上传、构建、历史任务、3D 图谱、问答和 API 交互。
- `frontend/ontology-workbench.js`：可编辑本体画布、实例 2D、前端草稿、规则高亮和配置表单。
- `frontend/mock-ontology.js`：无后端时用于产品验收的工业制造演示数据。

工作台通过 `lom:graph-rendered` 事件接收 `app.js` 已加载的 schema/instance 图，避免重写原有构建和问答流程。

## 四种视图

| 视图 | 数据 | 权限 | 主要行为 |
|---|---|---|---|
| 本体画布 | schema 转换后的工作副本 | 可编辑 | 新建、配置、删除、连线、节点拖动、缩放、平移、保存前端草稿 |
| 本体画布 3D | 当前本体工作副本 | 只读展示 | 复用原有 3D 星云、力导向、旋转、标签、选中和重置交互 |
| 本体实例 2D | 后端 instance graph | 只读 | 平面力导向布局、缩放、平移、详情、规则命中高亮、关系浏览 |
| 本体实例 3D | 原有 3D Graph | 只读 | 原有旋转、标签、问答高亮，接收规则高亮 |

画布 2D/3D 始终消费同一份本体工作副本；实例 2D/3D 始终消费同一后端实例图。四种视图都只是表现形式，后续接入时不得分别保存领域数据。

底部不再平铺四个页面按钮，而是使用“本体画布 / 本体实例”与“2D / 3D”两组正交开关。切换层级会保留当前维度，切换维度会保留当前层级；全局“本体智能体”入口也位于同一底部控制栏，顶部只保留本体结构编辑与保存操作。

## 画布语义

- 对象：26×26 圆点，蓝色。
- 规则：26×26 三角形，紫色。
- 行动：26×26 菱形，粉色。
- 关系：SVG `<line>` 直线箭头，端点裁切到节点边界。对象—对象为灰蓝实线，对象—规则为蓝色虚线，规则—行动为绿色虚线，行动—对象为粉色点线。
- 左侧“本体元素图例 / 元素连接图例”只在本体画布展示；实例视图展示本体规则列表。
- 画布节点层与 SVG 关系层使用同一 stage 坐标系；stage 四周预留可滚动空间，因此在 100% 下也能向任意方向平移。
- 普通重绘通过无参数动画帧闭包重新计算关系线，避免浏览器传入的帧时间戳被误用为 stage 尺寸；加载完成或点击空白区域后关系线不会消失。
- 节点描述默认开启，并固定跟随节点；关系名称固定在线段中点。关闭描述开关后，悬停或选中仍可显示对应信息。
- 自动生成/旧草稿位置会迁移到 `layoutVersion: readable-edges-v8`。首次布局以关系结构和标签框共同评分，优先减少非相邻关系线交叉和连线穿过无关节点，同时约束语义方向、边长及三类标签重叠。

## 交互

- 拖动画布空白区域：上下左右平移整个本体画布。
- 首次加载已有本体时，根据包含描述框的图谱边界自动选择一次总览缩放并居中；底部 `− / ＋` 或鼠标滚轮仍以视口中心/指针位置为焦点缩放，范围 20%–400%，“重置视图”恢复 100% 并居中。
- 单击节点：选中并在原有信息卡中显示摘要；双击对象、规则或行动打开详细配置。
- 单击已有关系：直接打开关系配置弹窗，关系点击热区不再被全画布节点容器遮挡。
- 普通拖拽节点：自由移动节点并保存布局，不会进入新建关系；节点坐标允许为负值，stage 根据图谱最小/最大坐标向四周扩展，因此左、上、右、下没有不对称硬边界。
- “新建关系”：进入两点选择模式，第一次选起点，第二次选终点，然后打开关系配置。
- `Esc`、点击画布空白或再次点击“新建关系”：取消连线模式。
- “节点描述”默认开启。节点说明固定锚定节点下方，关系说明固定锚定在线段中点；首次生成或加载时，布局器只移动节点，联合优化连线交叉、连线穿越与标签碰撞。描述开关、画布平移和缩放不会再次运行布局。
- “本体画布 3D”把当前工作副本转换为 schema 3D 数据后交给原 3D 渲染器，因此新建/修正的对象、规则、行动及关系会进入 3D 展示；该视图不提供结构编辑入口。
- 实例节点拖动：只调整当前实例 2D 的前端布局，拖动期间关闭节点位置过渡动画，使节点、关系线和关系文字在同一帧跟随指针；不修改实例领域数据，双击仍只读查看实例属性和关系。
- 本体实例 2D 复用同一套缩放、空白拖拽平移和重置行为，并使用与 3D 图谱一致的深色径向背景；首次加载时使用更大的力导向间距和锚定标签碰撞消解。缩放时实例节点、节点说明和线中点关系说明共用同一缩放倍率，保持绑定关系。

## 新建本体与模型设置

“新建本体”现在是统一的本体入口，包含本体名称、数据形态来源、本体描述，以及以下原有构建能力：

- 选择/拖拽一个或多个构建文档；选择后“开始构建本体”由禁用转为可用。
- 上传 YAML/YML 结构化配置，或导入 JSON/JSONL 已有本体。
- 刷新、加载和回放历史构建结果；点击加载/回放后弹窗退出，直接显示图谱。
- 文档任务完成并成功加载新图后，`lom:ontology-build-completed` 事件关闭弹窗；构建过程未完成或失败时弹窗不因空图重绘而提前关闭。
- 不选择输入时，底部“创建空白本体”仍可创建前端草稿。

该弹窗不使用全屏暗化或模糊蒙版，未被弹窗覆盖的画布仍然可见。右侧原“构建设置”面板只保留本体构建模型和问答推理模型；构建 API 使用前者，问答 API 使用后者。模型对比的三个隐藏选择器保留在弹窗外部的 parking 容器中，不会显示为弹窗底部模型块。上传、导入、加载与回放仍复用 `frontend/app.js` 中的原有事件流，不是前端伪按钮。

## 配置内容

对象配置包括名称、编码、状态、说明、来源追溯、属性和数据挂载。来源追溯只读展示 `sourceChunks`、`instanceIds` 及数量；属性与挂载保存来源，允许自动结果被人工补充或修正。

规则配置包括名称、编码、状态、作用对象、AND/OR 和条件列表。当前运算符包括空值、包含、比较和相等类运算。

行动配置包括行动类型（人工、API、调度任务、本体行动）、触发规则、目标对象、执行器/调用标识、行动计划、反馈说明和描述。

关系配置包括名称、编码、起终点、基数、字段映射和说明；允许对象、规则、行动之间建立关系。

## 规则列表与实例高亮

左侧规则列表只在本体实例 2D/3D 展示，内容包括规则作用对象、逻辑、条件和关联行动；本体画布只保留元素/关系图例。点击规则时：

1. 保持当前实例视图，不自动跳转到另一种视图。
2. 按作用对象和条件匹配实例；直接命中使用强高亮，一跳邻居使用关联高亮，其余元素降亮度。
3. 实例 2D 和 3D 使用同一实例节点、关系与命中集合；3D 复用原有 `applyHighlight`。
4. “清除高亮”同时清理规则状态。

当前匹配器属于展示级实现。后端字段不完整时会回退到作用对象节点，以确保规则仍能定位相关实例。它不能作为生产规则执行结果。

## 前端工作副本

浏览器存储 key：`lomOntologyWorkbenchWorkingCopyV1`。

工作副本版本：`contractVersion: ontology-workbench-v1`；主要字段为本体元数据、`nodes`、`edges`、`agents`、`sourceJobId`、`sourceMode`、`dirty` 和 `savedAt`。节点的 `kind` 为 `object | rule | action`，视图坐标保存在 `position`。

`agents` 是第一阶段留下的浏览器演示字段，不再是第三阶段的事实来源。全局“本体智能体”使用独立的后端资源、Pi Agent 会话和发布 API，详见 `ontology-agent-plan.md`。

`保存本体` 目前只是更新 `localStorage` 和 `savedAt`。保存完成后会显示独立反馈框并写出当前本体名称，但这不代表已经服务端持久化。页面初始化不会直接把本地草稿填入画布；当用户加载与 `sourceJobId` 匹配的本体 job 时才恢复该草稿，否则由 schema 图转换成新的工作副本。后端已有 `actions` 会通过 result 接口尽力补入画布。

右侧对话栏默认宽 540px，可由标题栏按钮折叠为 48px 窄栏；折叠后对话内容隐藏，左侧画布扩展并触发 2D/3D 尺寸重算。展开后恢复原来的对话、模型切换和构建设置内容。“构建设置”入口设置了固定最小宽度和不换行，避免文字竖排。

后端接入时必须把以下 UI 字段排除在领域契约之外：

- `position`、`layoutVersion`：画布布局，可单独保存。
- `dirty`：浏览器会话状态。
- `selected*`、高亮集合、连线预览：瞬时 UI 状态，不得持久化。

## 已知限制与验收清单

- 本地草稿只在用户加载匹配的本体 job 后恢复；换设备、清缓存或多人协作会丢失/冲突。
- 没有撤销/重做、版本历史和服务端校验。
- 数据挂载和后端规则求值未接入真实服务；智能体已经改为独立的真实后端资源。
- chunk 当前以 ID 列表展示，尚不能在画布内展开原文或定位页码/段落。
- 当前规则列表面向单层条件组；嵌套规则需在契约确认后设计。

产品验收重点：节点密度、标签显隐、三种形状辨识度、关系线型语义、规则列表信息量、节点拖动、缩放/平移手感、两点建关系的可发现性、弹窗字段是否符合业务语言。
