# 专用前端分支：feat/workspace-preview

该分支把已确认的聚焦单列工作空间设为默认前端。启动原 API 命令后，访问根地址即可自动打开新版。

```bash
git clone --branch feat/workspace-preview --single-branch https://github.com/AKak23/Knowledge_Engineering.git
cd Knowledge_Engineering/ontology_construct
uv sync --extra dev --python 3.12
# 按项目根 README 配置本地模型凭证，再启动：
uv run ontology-construct-api --host 127.0.0.1 --port 8000
```

- 默认新版：`http://127.0.0.1:8000/`（跳转至新版资源路径）
- 原版备用：`http://127.0.0.1:8000/legacy`
- 既有后端接口和原前端文件保留。浏览器草稿与文件库仍使用独立存储；后端任务由同一个服务管理。
- 下载部署需要配置自己的模型凭证；仓库不包含 `.env`、原始业务文件和本机运行结果。
- 本目录 `tests/browser-regression.cjs` 使用 Playwright + Chrome；`PLAYWRIGHT_MODULE` 可指定依赖路径，`PREVIEW_URL` 可设为 API 根地址。

以下为界面迭代阶段的历史记录，其中原默认入口和“未创建分支”等描述已由上述分支部署说明替代。

# KnoVa 隔离工作空间前端

2026-09-09。基于当前 LOM 前端的独立试验副本，参考 HTML A 的导航和入口组织，保留深色视觉与原生 JS 架构。

## 打开与回退

原 FastAPI 服务运行在 8000 时：

- 原版：`http://127.0.0.1:8000/`
- 新版：`http://127.0.0.1:8000/frontend/workspace-preview/index.html`

不需要更改 API 路由：原服务已挂载整个 `frontend/` 目录。关闭新版、返回原版地址即可恢复原来的界面。

只看界面与内置演示，可在仓库根目录执行：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8765/frontend/workspace-preview/index.html`。这个静态服务不能执行真实构建、导入和后端问答；“我的本体管理”中的内置演示支持画布、实例与演示问答。真实构建需用前述 FastAPI 地址。

## 范围与隔离

- `index.html`、`assets/` 是现有前端的独立快照；原入口、原 JS/CSS、后端代码均未改动。
- `workspace.js` / `workspace.css` 实现导航、新建页、本体管理、文件库和最近会话。
- 草稿与会话使用 `knovaWorkspacePreview*` localStorage 键；文件原始内容使用同名前缀的 IndexedDB，均不读写原版草稿键。
- 后端仍是同一个服务：历史构建可读取，点击构建/导入会真实新增任务。此次隔离的是界面代码与浏览器数据，不是复制一套后端或数据库。
- 文件库为本浏览器本地存储，不跨电脑同步。会话保存可阅读的文本记录，重新打开时展示记录；不是后端多轮会话持久化服务。
- 画布保存和本体修改仍沿用现有能力与限制。源本体实例通过后端重新加载，本地画布副本单独恢复。
- 原 3D 前端依赖的外部 Three.js / ForceGraph CDN 保留，离线时 3D 可能不可用。

## 新建流程

1. 填写本体名称、描述。选择上传文档、从文件库复用、上传结构化 YAML、导入已有 JSON/JSONL，或直接创建空白本体。
2. “先用一份资料试试看”加入一份冷却系统示例文本，点击开始后走真实构建，不假装生成业务本体。
3. 构建中显示原 API 的阶段、分块、详细日志、进度和质量信息，完成后自动进入原画布。失败留在新建页，保留资料供重试。
4. “我的本体管理”打开历史任务和本地副本，进入同一工作台，保留本体画布/实例、2D/3D、问答折叠和其他现有功能。
